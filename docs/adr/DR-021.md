# DR-021 — PB2 legacy authorization characterization

- **Status:** PB2-T08; this records the implemented §3.4 host baseline, not a
  future governance-policy decision. The owner's PB4 review remains pending.
- **Public boundaries:** `GET /api/health` is minimal public readiness under
  [DR-013](DR-013.md), whose owner approval remains **to be confirmed**.
  `POST /api/auth/login` accepts credentials without a session. The webhook
  requires its own HMAC/replay protocol, not a user role. A request that also
  supplies a cookie remains subject to the existing CSRF/session middleware.
- **Principal endpoints:** `/api/auth/me` accepts an active user session or a
  valid API-key service principal. Logout and reauthentication require a user
  session. API keys do not inherit user roles; ambiguous cookie-plus-bearer
  credentials are rejected. These are authentication mechanics, not general
  service permissions to access other routes.
- **Legacy role matrix:** Active `analyst`, `senior_analyst` and `admin` may use
  alert, incident, investigation, evidence, threat-intel and AI routes. Only
  active `admin` users may manage users or owned API keys. All such role gates
  call `require_roles` via the versioned `require_operation` policy. Unknown
  roles and service principals are denied, inactive/expired/revoked sessions are
  unauthenticated, and unsafe cookie requests require CSRF. Shared incident
  access is intentional; this baseline has no per-user incident ownership.
- **Change detection:** The contract test compares the characterized operation
  set with the actual host OpenAPI route set, so adding or removing a route
  requires an explicit matrix update. It exercises allow and deny outcomes over
  real sessions, service keys, an inactive session, an unlisted role and an
  anonymous caller. It is a PB2 contribution to the NFR-10 baseline, not a
  claim that future off/shadow/enforce governance parity already passes.
