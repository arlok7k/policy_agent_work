# DR-035 — PB4 browser session shell and direction scaffold

- **Status:** Implemented; subject to the PB4 baseline gate.
- **Context:** The guide requires a cookie/CSRF session shell, route guards,
  problem handling, i18n and RTL/LTR, but does not prescribe local UI behavior.
- **Decision:** A single same-origin Axios client addresses `/api` only,
  supplies the non-HttpOnly CSRF cookie in the mutation header, and signals
  session expiry on 401. It never stores credentials, tokens or session IDs in
  browser storage. Guards resolve `/api/auth/me`; 401 redirects to login while
  unavailable services show a retryable error. Login rechecks `/me`; errors
  expose only generic messages and safe correlation identifiers. The browser
  stores only language and direction preferences locally. The initial direction
  is RTL and the initial language English; either is switchable, with English
  and Arabic shell dictionaries as the i18n scaffold. The separate development
  CSRF cookie name anticipates the explicitly authorized development-only
  cookie opt-in; production remains on `__Host-` names.
- **Reason:** This fulfills the RTL requirement without confusing an outage
  with a logged-out session; server authorization remains authoritative.
- **Alternatives:** Persisting auth state in localStorage; trusting a client
  role as authorization; redirecting all failed requests to login; sending
  browser API requests to a separate origin.
- **Consequences:** Pages must treat content as text, and all mutations use the
  central client. The i18n catalog is a scaffold, not a complete translation
  of every future screen. UI role checks are cosmetic only.
