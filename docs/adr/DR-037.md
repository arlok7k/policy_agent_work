# DR-037 — PB4 host-page behavior and honest data presentation

- **Status:** Implementing; subject to the PB4 baseline gate.
- **Context:** The guide names pages but leaves their layout and browser-side
  interaction details open. The owner selected the dark SOC console and the
  narrowly scoped host APIs in DR-034 and DR-036.
- **Decision:** Use real host summaries, cursor-paginated alert/incident/action
  lists and the append-only command log. Dashboard totals are derived only
  from the returned severity/status counts; no simulated metrics are fabricated.
  Investigating an alert opens the resulting incident. Response requests use
  the server catalog and explicitly label connector execution as simulated.
  Approvals, rejection, rollback and switch changes require an explicit
  confirmation and are sent to the server without optimistic updates. The
  activity view offers a manual refresh because execution is asynchronous.
  The UI hides decisions/switch controls from ineligible roles and hides
  self-approval; the server remains the authority. Alert and evidence data are
  rendered as text. Intel results identify their mock/degraded status. Settings
  contain no operational policy, and a local direction choice overrides the
  shared presentation default. Placeholders are labelled as such.
- **Alternatives:** Mocking data in the browser, inferring execution from action
  status, or treating hidden buttons as authorization.
- **Consequences:** Approval queues show the currently loaded page, and the
  operator must refresh to observe later asynchronous work. Translations beyond
  the shell remain a future i18n task, not a claim of full Arabic localization.
