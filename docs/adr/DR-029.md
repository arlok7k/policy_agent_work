# DR-029 — Structured simulation-only connectors

- **Status:** PB3-T05; the Celery execution and HTTP routes follow in PB3.
- **Owner decision (verbatim):**
  > - Connectors are simulated: they write to executed_commands and NEVER perform network I/O.
  >
  >   Add a socket-level test proving no connection is attempted.

## Decision

`Connector` is an ABC; `SimulatedWazuhConnector` and `InternalConnector` accept
only a catalog-defined action and a caller-supplied, transactionally locked
safety snapshot. They resolve the fixed command from the catalog, re-run the pure
Safeguards for the actual phase, check state/attribution and the automation-only
Kill Switch, and add one structured `simulated=true` record to the caller's
`executed_commands` transaction. They do not open a socket, resolve a host,
spawn a process, invoke a shell or provide a real connector. `permanent_block`
records the simulated Wazuh command `firewall_drop`. Internal actions record
intent only; they do not change real IOC, mute, escalation or notification state.

The caller must already hold the safety/action locks and revalidate human
approval and actors; a `SafetySnapshot` is a data object, not an authorization
capability. The connector merely adds the ORM record; the caller commits it with
its transition and activity. Database transport is the host application's
separately configured connection, not a connector-created network connection.
The socket-level tests intercept connection and address-resolution calls while
invoking both connectors, as well as checking the committed database records.
An untrusted action cannot supply its own shell command or override connector
selection. The database unique action/phase constraint protects redelivery.
