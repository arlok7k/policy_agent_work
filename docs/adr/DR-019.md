# DR-019 — PB2 mock AI contract and data minimization

- **Status:** Implementing PB2-T06 under the PB2 shared-tenant contract in
  [DR-015](DR-015.md).
- **Context:** PB2 requires deterministic structured mock summaries,
  recommendations and comprehensive analysis, but gives no payload shapes.
- **Decision:** Each endpoint accepts an existing `alert_id` and returns HTTP
  200 with `mock=true` and a typed, deterministic result. Missing alerts return
  404. The application installs only `MockLLM`; no real model or network client
  is implemented. Recommendations are informational text, not executable
  response actions. All active legacy roles may use these endpoints.
- **Data boundary:** The provider receives a narrow alert context containing
  only the UUID, source, rule ID, severity, status, optional agent and IPs. It
  receives neither raw alert JSON nor any governance record. Inputs and outputs
  remain JSON data; no HTML is rendered, and responses are not cached.
- **Alternatives:** Accepting arbitrary prompts or raw alert/governance data
  would enlarge the data boundary and make the mock less deterministic. Actual
  LLM integrations belong outside PB2 and require a separate decision.
