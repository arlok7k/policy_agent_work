# DR-001 — PB1 runtime and dependency versions

- **Status:** Accepted for PB1; the Cedar binding's behavior remains a P1 spike.
- **Context:** Specification §3.4 requires explicit, hashed version choices. The
  checkout contains no existing stack or lock files. At selection time the Cedar
  PyPI distribution advertised CPython 3.15 wheels, but that does not prove the
  P1 engine contract.
- **Decision:** Pin CPython 3.15.2. Reserve Node 26.13.1, PostgreSQL 18.6 and
  Redis 8.2.11 for the baseline. PB1 uses FastAPI 0.162.5, Pydantic 2.14.3,
  pydantic-settings 2.16.2, SQLAlchemy 2.1.8, Alembic 1.20.1, psycopg 3.3.9,
  argon2-cffi 25.1.0 and Uvicorn 0.54.0. Pytest 9.2.0, pytest-cov 7.1.0,
  HTTPX 0.28.1, Ruff 0.17.5, mypy 2.4.1, pre-commit 4.7.0, pip-audit 2.10.1,
  pip-licenses 5.5.5, detect-secrets 1.5.0 and pip-tools 7.6.2 support
  testing and checks; setuptools 84.2.1 is the build backend.
  The exact transitive dependency hashes are maintained in `requirements.lock`.
- **Reason:** These versions meet the specified major-version constraints and
  have current releases compatible with the selected interpreter. PostgreSQL is
  tested as PostgreSQL, never substituted with SQLite. Node, Redis and the
  engine are not implemented in PB1.
- **Alternatives:** The sandbox's CPython 3.11 was rejected as the deployment
  pin because §3.4 requires the newest stable interpreter supported by the
  proposed binding. It can still be used to bootstrap the local toolchain.
- **Consequences:** P1 must actually test Cedar on the deployed interpreter;
  the mere existence of a wheel is not evidence that the engine spike passes.
  Any resulting version change requires another DR and regenerated hashes.
