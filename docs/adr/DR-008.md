# DR-008 — Legacy role dependency

- **Status:** Accepted by the implementation agent; implements §3.4 and the
  DR-006 boundaries, whose owner approval remains to be confirmed.
- **Decision:** `current_user` reads a cookie session, current user and role
  from PostgreSQL on every request, and denies missing, inactive, revoked or
  expired identities. `require_roles` is a generic deny-by-default dependency:
  route declarations pass their allowed legacy roles explicitly, without a
  role hierarchy or client-supplied role claims. Cookie-only admin operations
  never elevate a service key into its owner's role. Future governance wraps
  these checks; it must not replace them before the PB4 baseline review.
- **Alternative:** Caching a role in the session or trusting a header would
  delay role changes or allow a forged role. Neither is acceptable.
- **Consequence:** Each protected request depends on a database read. Mutation
  services must revalidate identity and role within their transaction when
  taking their row locks, so disabling or demoting a user cannot race a write.
