# DR-042 — Nginx edge, forwarded-header overwrite and TLS template

- **Status:** Implemented; real Compose end-to-end verification pending.
- **Context:** PB4 requires a static frontend, `/api` proxy, SPA fallback,
  security headers, bounded requests, a TLS-ready configuration and the
  explicit proxy boundary selected in PB4-FU01.
- **Decision:** An unprivileged Nginx server listens on 8080, serves the built
  static frontend and proxies `/api/` without changing its path. It overwrites
  `X-Forwarded-For`, `X-Real-IP` and `X-Forwarded-Proto` from its connection,
  removes other forwarded-host/port/standard Forwarded values, and does not
  append attacker-controlled chains. The backend trusts only the dedicated
  internal Nginx address and the ASGI worker never rewrites the socket peer.
  A 1 MiB edge request limit precedes the stricter application webhook limit.
  The CSP restricts scripts, styles, connections and assets to the same origin,
  disallows inline scripts and framing; X-Frame-Options, nosniff, no-referrer
  and a restrictive Permissions-Policy are also applied. HSTS is emitted only
  on TLS responses. Nginx access logs are disabled rather than reopening a
  container output pipe as a non-root user; backend request logging remains
  sanitized and excludes query strings and credential headers.
  An inactive TLS server template references operator-provisioned certificate
  and key files; no private key or certificate is supplied by this repository.
- **Alternatives:** Trust a forwarded chain from any client, terminate only at
  an unspecified external proxy, ship self-signed production certificates, or
  use a permissive inline-script CSP. These do not meet the selected boundary.
- **Consequences:** HTTP is local development only. Operators must explicitly
  mount and enable TLS, publish the TLS port and disable/redirect production
  HTTP. If another ingress proxy sits in front of Nginx, its address becomes the
  observed peer; extracting a true earlier client IP needs a separately reviewed
  trust boundary. Nginx and real-browser security checks remain required.
