# DR-044 — Reserve the trusted Nginx address outside the Docker allocation pool

- **Status:** Implemented; real Compose verification pending.
- **Context:** The first full-stack CI startup failed when Nginx was starting.
  The owner supplied the sanitized daemon message, `failed to set up container
  networking: Address already in use`. The earlier network config specified
  subnet `172.30.42.0/24` but no narrower automatic allocation range. Nginx
  starts after other services and requests `172.30.42.2` as a static address.
  A collision with an automatically allocated address is consistent with the
  message, but the message alone does not establish which address was occupied.
  Docker's documented way to reserve a static address is to put it outside the
  dynamic `--ip-range` within the subnet: [Docker network connect](https://docs.docker.com/reference/cli/docker/network/connect/#network-implications-of-stopping-pausing-or-restarting-containers).
- **Decision:** Keep the internal subnet `172.30.42.0/24`, Nginx's dedicated
  address `172.30.42.2` and `TRUSTED_PROXY_IPS=172.30.42.2`. Set the internal
  automatic allocation range to `172.30.42.128/25`, outside the static address.
  A configuration test iterates static IPv4 and IPv6 service addresses, ensures
  their containing IPAM pools specify a dynamic range that excludes them, and
  checks the backend trusts exactly the Nginx address. Mutation tests exercise
  collisions across services and networks and a proxy-trust mismatch.
- **Alternatives:** Change or remove the trusted proxy address, rely on startup
  order, or place a static address in the automatic pool. These either change
  the approved security boundary or leave the address vulnerable to reuse.
- **Consequences:** Existing Compose networks must be recreated to use the new
  IPAM configuration. Stop the stack and remove its Compose network without
  deleting persistent volumes; do not remove data to resolve the conflict. If
  the subnet overlaps a host network, an operator must select a non-conflicting
  subnet, keep the static address outside its dynamic range, and configure the
  exact same Nginx address as the only trusted proxy. The real Compose health
  check and full browser smoke remain necessary. This amends [DR-041](DR-041.md).
