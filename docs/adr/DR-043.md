# DR-043 — PB4 CI gates and isolated test-bridge lifecycle

- **Status:** Implementing; final-head CI remains mandatory.
- **Context:** PB4 adds frontend, container and browser gates without weakening
  the existing no-IP backend tests, migration checks or dependency/license and
  secret scans. A local isolated run passed its tests but emitted asynchronous
  bridge teardown errors because relay tasks had no strong lifetime reference.
- **Decision:** Preserve the backend job and no-IP namespace preflight. Track
  bridge relay tasks, cancel/await them at shutdown, and fail with a sanitized
  error if a relay unexpectedly fails. Add a separate pinned Node frontend job
  and an ephemeral Docker Compose job that validates config, builds, starts,
  checks health, and runs the real end-to-end security smoke in the opt-in
  test client described by [DR-045](DR-045.md). The Compose CI bootstrap uses
  explicitly generated, ignored throwaway development secrets. On failure,
  service diagnostics are displayed only after exact secret values and URL
  passwords are redacted; if redaction cannot run, raw logs are never printed.
- **Alternatives:** Disable isolation or suppress bridge exceptions, use mocked
  browser requests as the end-to-end gate, or expose raw test credentials in CI.
- **Consequences:** CI requires Docker, Linux network namespaces, access to the
  pinned package/image registries and a Playwright-compatible browser. Passing
  local mocked-browser tests does not substitute for the real Compose smoke.
