# DR-014 — Development-only seed behavior

- **Status:** Accepted by the implementation agent within PB1-T11's specified
  development-only seed requirement.
- **Decision:** The seed refuses every `ENV` except exactly `development`
  before reading configuration or connecting. It uses the existing restricted
  runtime database role and requires an empty `users` table. Under one database
  transaction and a user-table lock, it creates one account for every role in
  the role catalogue, using the normalized role name as the username. Each
  password is supplied only through `SEED_<ROLE_NAME>_PASSWORD` environment
  variables and must satisfy the configured password policy. Every insertion
  receives a correlated activity entry. A missing or invalid password, existing
  user, DB/audit failure or unsafe runtime principal aborts the whole seed.
- **Alternatives:** Fixed example passwords or unconditional upserts risk
  credential disclosure or accidental overwrites. Hard-coding a separate role
  list could diverge from the seeded catalogue.
- **Consequences:** Rerunning is deliberately not idempotent; it refuses to
  overwrite existing users. `ENV` is a deployment trust boundary: operators
  must not point a development configuration at a production database. The
  script never prints passwords, hashes, database URLs or exception text.
