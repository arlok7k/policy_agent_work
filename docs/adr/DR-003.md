# DR-003 — PB1 configuration and secret-file loading

- **Status:** Accepted for PB1; secret values are provisioned by the operator.
- **Context:** PB1-T02 requires typed environment settings, Docker-secret file
  support and startup refusal for missing secrets. §3.4 requires PostgreSQL and
  a session signing key, but does not specify environment variable names or
  precedence between inline and file values.
- **Decision:** Require `ENV`, `DATABASE_URL` or `DATABASE_URL_FILE`, and
  `SESSION_SIGNING_SECRET` or `SESSION_SIGNING_SECRET_FILE`. Exactly one source
  is allowed per secret; conflicts, unreadable files, empty values and invalid
  settings fail startup with a generic error. PostgreSQL URLs must use the
  `postgresql+psycopg` SQLAlchemy driver. The signing secret must contain at
  least the SHA-256 digest length in bytes, and the operator must provide it
  from a cryptographically secure generator; length alone is not proof of
  entropy. A single terminal newline is removed from secret files.
- **Alternatives:** Silent precedence or a development fallback secret could
  hide a misconfiguration or make production insecure. Reading `.env` files
  implicitly is avoided; operators explicitly export values or use secret files.
- **Consequences:** Application startup and tests must supply explicit settings.
  Example paths contain no actual secrets. This decision does not define the
  public authentication API or its authorization semantics.
