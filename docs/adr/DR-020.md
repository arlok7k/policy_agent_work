# DR-020 — PB2 incidents, investigation and evidence boundaries

- **Status:** Implementing PB2-T07 using the shared-tenant contract selected in
  [DR-015](DR-015.md); exact schemas/statuses are exported at PB2-T09.
- **Incident contract:** Creation accepts a bounded title, optional bounded
  description and a configured maximum number of distinct existing alert IDs;
  returns 201. The same alert-count cap applies when investigation adds a new
  association; repeated investigation of an existing association is allowed.
  Lists and evidence lists use the same timestamp/UUID keyset cursor as alerts. A missing incident, alert or referenced association returns
  a generic 404. All three active legacy roles may create, investigate and read
  any incident; this single-tenant baseline has no per-user ownership rule.
- **Investigation:** An optional `incident_id` links the alert to that incident;
  otherwise reuse the oldest already-linked incident or create an open one.
  Lock the alert while choosing and linking so concurrent investigations cannot
  independently create incidents for the same initially unlinked alert. Lock and
  revalidate the actor's actual session and role in the same transaction.
- **Enrichment and audit:** Use the first available source or destination IP for
  mock threat intelligence, and the minimized alert context for MockLLM. If the
  alert has no IP, report no intelligence result rather than inventing an IP or
  verdict. Store incident-scoped evidence for the intelligence outcome and mock
  analysis, set alert status to `investigating`, and append a `case_activities`
  event in the same DB transaction as incident/association/evidence changes.
  Cache records follow [DR-018](DR-018.md); an orphan Redis entry after rollback
  is ignored without a committed DB row. Failure of enrichment or audit rolls
  back the investigation rather than claiming success.
- **BOLA/IDOR:** The evidence list first verifies the incident and filters by its
  ID; the database also rejects evidence linking an alert to an unrelated
  incident. A caller may see any existing incident under the specified shared
  legacy matrix but cannot use one incident's URL to obtain another's evidence.
- **Alternatives:** User-owned incidents would change §3.4's authorization
  baseline. Enriching outside the transaction without a recheck could record a
  mutation after the actor's session or role was revoked.

## Wire contract and outcomes

- `POST /api/incidents` accepts `{title: string, description: string|null,
  alert_ids: UUID[]}`; description and the array are optional, and the array
  defaults to empty. Title/description are stripped and individually limited by
  `INCIDENT_MAX_TEXT_CHARS`; a title must be nonempty. The configured
  `INCIDENT_MAX_ALERTS` bounds distinct associations. Success is **201** and the
  incident view is `{id: UUID, title: string, description: string|null, status:
  string, created_at: timestamp, updated_at: timestamp, alert_ids: UUID[]}`.
  Status is initially `open`; alert IDs are sorted.
- `GET /api/incidents` returns **200** `{items: IncidentView[], next_cursor:
  string|null}`. `GET /api/incidents/{incident_id}` returns **200** and a view.
  Both incident and evidence lists use the existing configured page limits.
- `POST /api/alerts/{alert_id}/investigate` accepts `{incident_id: UUID|null}`
  with the member optional, and returns **200** `{incident: IncidentView,
  intelligence: IntelResult|null, ai: ComprehensiveResult}`. Results follow
  [DR-018](DR-018.md) and [DR-019](DR-019.md). A missing IP yields `null`
  intelligence. Repeated calls may append new evidence, but do not duplicate the
  incident association; the alert status becomes `investigating`.
- `GET /api/incidents/{incident_id}/evidence` returns **200** `{items:
  EvidenceView[], next_cursor: string|null}`. Each view is `{id: UUID,
  incident_id: UUID, alert_id: UUID|null, kind: string, data: object, created_at:
  timestamp}`. Investigation appends `threat_intel` data `{checked: true,
  result: IntelResult}` or `{checked: false, reason: "no_indicator"}`, and
  `ai_comprehensive` data `{result: ComprehensiveResult}`.
- Malformed bodies, extra members, invalid UUIDs, invalid cursors, duplicate
  alert IDs, blank/oversized text and NUL text return **400**; anonymous or
  revoked sessions **401**; disallowed roles or missing CSRF **403**; missing
  referenced resources **404**; an exceeded alert-count or page-size limit
  **422**; database/cache failure, an unconfigured threat provider or mock-AI
  adapter failure **503**. Unexpected internal/provider errors remain generic
  **500** responses. Error responses do not disclose inputs.
