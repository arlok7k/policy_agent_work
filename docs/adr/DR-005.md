# DR-005 — PostgreSQL sessions and disposable migration tests

- **Status:** Accepted for PB1.
- **Context:** PB1-T03 requires real PostgreSQL sessions and Alembic up/down
  verification; the specification does not prescribe test isolation or whether
  the migration process should receive the session-signing secret.
- **Decision:** Use synchronous SQLAlchemy sessions, `pool_pre_ping`, hidden SQL
  parameters and explicit transaction boundaries. Alembic reads only the
  database URL (inline or secret file), never the session-signing secret.
  Database tests require both `TEST_DATABASE_DISPOSABLE=1` and a PostgreSQL
  database whose name ends `_test`; each test uses and drops a randomly named
  schema inside that disposable database. CI supplies a throw-away PostgreSQL
  18.6 service with trust authentication on its isolated runner, not production
  credentials. An initial test-only revision exercises Alembic before the real
  001–003 revisions are introduced in PB1-T04.
- **Alternatives:** SQLite or mock connections cannot verify PostgreSQL DDL and
  privileges. Requiring the signing key for migration would violate least
  privilege. A developer's default database is never used as an implicit test
  target.
- **Consequences:** Database tests fail, rather than skip, if the disposable
  database is not explicitly configured. An empty Alembic version table is
  migration metadata, not a host application table; all application objects
  must be absent after a downgrade to base. The disposable flag and suffix are
  safeguards, not proof that a database contains no valuable data: the operator
  must only point them at a genuinely disposable database.
