# DR-041 — Compose isolation, runtime identity and development secrets

- **Status:** Implementing; Compose and real-browser verification pending.
- **Context:** PB4 requires a full, non-root Compose stack, a restricted runtime
  database identity, internal PostgreSQL/Redis, Docker secrets, and the owner
  selected **“Development bootstrap (recommended)”**.
- **Decision:** Build a pinned Python backend with Gunicorn 27.0.1 and
  uvicorn-worker 0.4.0; a custom worker disables proxy-header rewriting so the
  application can validate the actual peer. A separate migration job receives
  owner credentials and provisions a non-elevated login inheriting only the
  `hpb_app` database role. API, worker and Beat receive only the runtime URL.
  PostgreSQL 18.6 and Redis 8.2.11 run exclusively on an internal network;
  only Nginx joins the edge and publishes a port. Nginx has a dedicated internal
  IP, matching the explicit backend trusted-proxy configuration. Containers run
  as non-root with dropped capabilities and health checks. The frontend is a
  static Node 26.13.1 build copied into Nginx 1.30.6, not a separate runtime.
  Redis instances are unauthenticated only on the internal network and use
  ephemeral data; durable response intent remains in PostgreSQL and Beat
  reconciles it. Production secrets are operator-provisioned files; an explicit
  development-only bootstrap generates ignored throwaway files without
  overwriting existing files. It uses a private host directory; its file modes
  account for local Compose's non-remapped file-backed secret mounts.
- **Alternatives:** Share an elevated owner URL with the application, publish
  database ports, trust arbitrary internal forwarding, or silently generate
  production secrets. These violate least privilege or the selected boundary.
- **Consequences:** Local HTTP requires the separate explicit cookie opt-in.
  Production needs TLS and operator-managed secrets, file permissions, image
  refresh, backups and monitoring. Redis/network isolation is not a defense
  against a compromised service attached to that network. A persisted database
  and its secret files must be retained or rotated together; bootstrap refuses
  to overwrite them. Real Compose, proxy, browser and security tests remain
  mandatory before the PB4 gate.
