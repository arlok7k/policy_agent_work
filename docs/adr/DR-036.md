# DR-036 — PB4 host read APIs and presentation settings

- **Status:** Implemented; subject to the PB4 baseline gate.
- **Context:** The documented UI requires settings, executed-command history
  and the current Kill Switch state. PB3 provides none of these reads, and an
  action's status is not an executed-command log. The owner chose **“Add minimal
  endpoints (recommended)”** and **“Presentation settings (recommended)”**.
- **Decision:** Add `GET /api/response/commands` over the append-only
  `executed_commands` table, with descending ID pagination, optional action
  filter and the existing all-active-roles `response_read` guard. Add
  `GET /api/response/kill-switch` under the same guard, allowing a null initial
  `changed_by`. The owner additionally selected **“Read-only presentation
  endpoint (recommended)”**: `GET /api/presentation` exposes only display name
  and default direction to all active roles, while `GET /api/settings` and
  `PATCH /api/settings` remain restricted to active
  administrators. The only settings are a display name and default `ltr`/`rtl`
  direction; names use the existing `USERNAME_MAX_CHARS` bound. PATCH requires
  CSRF, locks and revalidates the live admin/session, and writes its audit event
  in the same transaction. An audit failure rolls back the change. Host-only
  migration `009_host_settings` creates one minimally granted singleton table;
  it does not alter an existing table. Subsequent governance migrations must
  begin after the actual host head rather than assuming revision 009 is free.
- **Reason:** These additions deliver the real UI data without conflating queued
  actions with executed commands or exposing operational/security controls.
- **Alternatives:** Fake command/state values; editable security thresholds;
  reusing response action statuses as a command log; exposing settings to
  non-administrators through the administrative API. Each would violate the selected scope or security model.
- **Consequences:** OpenAPI, role characterization and migration expectations
  include the new operations/revision. Non-admin users can read only the two
  non-sensitive presentation values, not the administrative endpoint. Local
  direction choices override the workspace default. Existing PB1–PB3 behavior
  is otherwise unchanged.
