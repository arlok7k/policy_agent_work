# DR-045 — Disposable Playwright smoke on the Compose edge network

- **Status:** Implemented; real full-stack smoke verification pending.
- **Context:** PB4 requires a real signed-webhook-to-response browser workflow,
  role/CSRF/XSS/cookie security checks, and evidence that the UI does not reach
  data services or off-origin endpoints. Local mocked browser checks cannot
  establish these properties for the Compose stack.
- **Decision:** Add an opt-in `e2e` Compose profile with a non-root, test-only
  Chromium/Playwright container attached only to Nginx's edge network. Its
  locked Playwright package installs its matching Chromium; web security stays
  enabled. The harness requires explicit disposable development mode, generates
  independent throwaway credentials in memory, and invokes the existing seed
  command, which refuses a nonempty user table. The test client receives only
  those credentials and the disposable webhook signing secret. It first checks
  that the backend can connect to PostgreSQL and both Redis services, then
  probes their actual internal addresses from the edge client. The existing
  configuration test also ensures that only Nginx publishes a host port.
- The real browser checks same-origin static assets and SPA navigation while
  requiring all data requests to use `/api/`; it rejects other origins and
  WebSockets. It exercises route guards, CSP, inert hostile alert text,
  development-cookie attributes, missing-CSRF rejection, analyst UI/API denial,
  a distinct senior approval, the real simulated-command log, Kill Switch,
  modal focus, RTL/LTR, slow responses, pagination and mid-action session
  revocation. Production Secure/`__Host-` cookie behavior remains covered by
  the isolated backend suite rather than being inferred from HTTP dev cookies.
- A non-string `Redacted` wrapper is used for test credentials and tokens.
  Passwords and keys are never command-line arguments. Diagnostics remain
  visible after masking known secrets, signatures and credential headers;
  screenshots, video and traces are disabled because they can retain secrets.
  GitHub check annotations include sanitized failure output, in addition to
  normal logs. The test image is not part of the production Nginx image.
- **Alternatives:** Mock API responses as the acceptance test, attach the browser
  to the database network, use fixed credentials, persist browser traces, or
  run a mutating smoke against an ordinary persistent deployment.
- **Consequences:** CI needs Docker, browser downloads and a disposable stack.
  Test results may include synthetic alerts, an executed *simulated* command,
  and an engaged Kill Switch; never point the harness at production or useful
  development data. Network isolation does not protect against Docker-host
  administrators. Real Compose/Playwright results and the PB4 owner gate remain
  separate requirements.
