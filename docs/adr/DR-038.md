# DR-038 — Reusable accessible host UI primitives

- **Status:** Implementing; subject to the PB4 baseline gate.
- **Context:** PB4 requires table, badge, dialog, form field, toast and
  pagination primitives that the P9 governance screens can reuse.
- **Decision:** Use semantic tables with accessible captions, textual status
  badges, labelled pagination and form controls, persistent dismissible live
  notifications, and the browser's native modal `<dialog>` with Escape handling
  and focus restoration. The response confirmation and settings screens use
  these primitives now. Component tests cover names, validation descriptions,
  disabled controls, modal dismissal/focus and notification dismissal.
- **Alternatives:** Unlabelled div tables, color-only statuses, custom incomplete
  focus traps, or time-limited notifications that may disappear before reading.
- **Consequences:** Supported production browsers must implement native modal
  dialogs. JSDOM uses a test-only modal API shim, so real-browser interaction is
  also checked in the Playwright smoke rather than inferred from JSDOM.
