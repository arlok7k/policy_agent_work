# DR-018 — PB2 mock threat intelligence and cache failure semantics

- **Status:** Implementing PB2-T05 under the selected shared-tenant PB2 contract.
- **Context:** PB2 specifies provider interfaces, deterministic mocks, a bulk
  cap, PostgreSQL and separate Redis caching, and a degraded timeout response,
  but leaves verdict shapes, TTLs and cache outage behavior open.
- **Provider contract:** Input is a canonical IPv4 or IPv6 address. The only
  provider installed in the running application is `MockProvider`, which
  deterministically maps loopback to `benign`/0, other private/reserved addresses
  to `suspicious`/50, and other addresses to `unknown`/no score. These are
  synthetic test results, **not threat intelligence facts**; every successful
  verdict says `mock=true` and names `mock` as its source. Real VirusTotal,
  AbuseIPDB and OTX adapter classes contain no networking and only raise
  `NotConfigured`. No real provider is configured or reachable in PB2 tests.
- **Timeout:** Enforce the configured provider deadline. A timeout returns an
  explicit `unknown`, `score=null`, no sources and `degraded=true`; it is never
  persisted as a successful verdict or presented as a fabricated reputation.
  Other provider/configuration failures fail closed rather than inventing data.
- **Cache:** PostgreSQL is authoritative for verdict and expiry, measured with
  the database clock. Redis holds a bounded-TTL copy in the separate cache
  instance. Each hit is checked against the live database row; missing, stale
  or inconsistent Redis entries are repaired from PostgreSQL. A cache miss
  invokes the mock and stages the PostgreSQL row before writing Redis; the
  caller commits its database transaction. If Redis is unavailable the API
  returns 503 and the transaction is rolled back. If a later database rollback
  leaves an orphan Redis copy, subsequent reads ignore it without a matching
  committed DB record. Redis values are not evidence of a verdict on their own.
- **API:** `check-ip` accepts `{indicator}`; `bulk-check` accepts `{indicators}`
  and preserves order. The configured cap is checked before any lookups. Cache
  stats report fresh and expired PostgreSQL row counts and Redis availability,
  without an unbounded Redis key scan. All three active roles are allowed by
  the legacy policy. Exact schemas and status codes are exported at PB2-T09.
- **Limits:** Provider timeout, cache lifetime and maximum batch size are
  required operator-configured positive settings, not hidden constants.
